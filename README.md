# 차일지 (베타)

내 차 소모품 교체 주기·자동차 검사 일정을 챙겨주는 수첩 + 차종별 자동차세 계산 + 유지비(TCO) 비교.

- **수첩**: 차 등록 → 소모품 교체 기록 → D-day 알림. 모든 기록은 브라우저(localStorage)에만 저장되며 서버로 전송되지 않습니다. JSON 내보내기/가져오기로 백업.
- **차종별 자동차세**: 국산·수입 인기 차종(승용·화물·승합)의 연식별 자동차세·연납 할인 표 (지방세법 제127조 기준). 차종 목록은 `data/vehicles.json`.
- **유지비 비교**: 두 차종의 월 유지비(자동차세+연료비+보험+감가)를 나란히 비교.

## 개발

노빌드 바닐라 HTML/CSS/JS. 차종별 페이지는 Python으로 정적 생성.

```bash
python3 -m http.server 8347        # 로컬 실행 → http://127.0.0.1:8347
python3 scripts/build.py           # data/*.json 변경 시 tax/ 페이지·sitemap.xml·ads.txt·손 페이지 마커 재생성
```

`tax/`는 빌드 전용 폴더예요. 빌드는 더 이상 만들지 않는 차종 페이지(차종 삭제·slug 변경·`sample` 전환·배기량 비움)를
지우고 그 이름을 출력합니다(`tax/index.html`·`tax/calculator.html`은 빼고). 손으로 만든 페이지는 `tax/`에 두지 마세요.

빌드는 공유 썸네일(`og/*.png`, 카카오톡·SNS 미리보기)과 홈 화면 아이콘(`icons/`, `favicon.ico`)도 함께 그립니다.
Pillow가 필요합니다: `pip3 install --user pillow`. 없으면 빌드는 그대로 되지만 새 이미지를 그리지 못하고,
금액이 바뀌어 낡은 썸네일은 og:image에서 빠집니다. 폰트는 `scripts/fonts/`의 Pretendard(OFL)를 씁니다.
썸네일 디자인을 바꾸면 `scripts/images.py`의 `RENDER_VERSION`을 올리세요 — 전부 다시 그려지고 URL의 `?v=`가 바뀌어 카톡 캐시도 갱신됩니다.

손으로 쓰는 루트 페이지(`index.html`·`tco.html`·`privacy.html`·`terms.html`·`about.html`)는 빌드가 만들지 않아요.
빌드는 그 안의 마커 구간만 `data/site.json` 값으로 채웁니다(아래 '손 페이지 마커 규칙').
상단 내비·푸터는 생성 페이지와 같은 계약 마크업을 씁니다(DESIGN.md '상단바·내비'·'푸터').

로직 테스트 (macOS 내장 JavaScriptCore):

```bash
jsc js/derive.js tests/derive.test.js
jsc js/storage.js tests/storage.test.js
```

node가 있으면 `node tests/run.js` 하나로 전부 돌아갑니다. 각 테스트 파일 첫 줄의 `jsc 실행: jsc …` 주석을 읽어 같은 파일을 로드하므로, 새 테스트도 첫 줄만 그 형식으로 쓰면 자동으로 포함돼요.

세율·소모품 주기 등 모든 상수는 `data/*.json`에 있습니다. 계산 결과는 참고용이며 실제 고지 세액은 위택스에서 확인하세요.

## 검사

커밋하기 전에 한 줄만 돌리면 됩니다. 깃허브에 push하거나 PR을 열면 같은 검사가 자동으로 돌아요(Actions 탭 '자동 검사').

```bash
python3 scripts/check.py          # 전부 (1~2초)
python3 scripts/check.py data     # 하나만: data · tests · parity · build · links
```

| 검사 | 잡아내는 것 |
|---|---|
| 데이터 (`scripts/validate_data.py`) | `data/*.json` 실수 — JSON 문법, slug·id 중복, 배기량·연비·연식 범위, 세율표 순서, 공제율 단위(5% → 0.05). `site.json`의 애드센스 값(`pub-`+16자리, `ca-pub-`으로 넣은 실수, 슬롯은 숫자만, 모르는 슬롯 이름·publisherId 없는 슬롯은 경고)과 `contactEmail` 형식. 손 페이지 광고 마커 이름(`<!-- adsense:slot tcoEnd -->`)이 계약에 없는 이름이면 오류(오타가 나면 광고가 소리 없이 빠져서), 슬롯 ID·`contactEmail`을 채웠는데 받을 마커가 없으면 경고 |
| JS 테스트 (`node tests/run.js`) | `tests/*.test.js` 전부. node가 없으면 macOS jsc로 돌리고, 둘 다 없으면 건너뜀(CI에서는 돌아감) |
| 세액 일치 (`scripts/check_tax_parity.py`) | 차종 페이지(`build.py`)와 계산기(`js/tax-calc.js`)의 세액이 모든 배기량·차령에서 1원까지 같은지 |
| 빌드 최신 여부 (`check.py build`) | `data/*.json`이나 `build.py`를 바꾸고 빌드를 안 돌렸는지. 임시 폴더에서 빌드해 `tax/`·`og/`·`icons/`·`favicon.ico`·`robots.txt`·`sitemap.xml`·`ads.txt`, 그리고 손 페이지(루트 `*.html`)의 마커 구간과 비교해요(작업 중인 파일은 안 건드림). `site.json`의 `adsense`·`contactEmail`만 바꾸고 빌드를 안 돌리면 `[새로 생김] ads.txt`·`[바뀜] index.html` 등으로 잡혀요. `sitemap.xml`은 날짜(`lastmod`)만 빼고 비교해 차종 추가·삭제가 빠진 낡은 sitemap을 잡고, 빌드가 더 이상 만들지 않는 `tax/` 페이지·썸네일이 남아 있으면 '지워짐'으로 알려 줘요. 광고를 두지 않는 페이지 — 수첩(`index.html`)·소개(`about.html`)·개인정보처리방침(`privacy.html`)·이용약관(`terms.html`) — 에 광고 슬롯 마커나 광고 코드(`adsbygoogle`)가 있어도 실패해요 |
| 링크·앵커·공통 크롬 (`scripts/check_links.py`) | 모든 페이지의 깨진 내부 링크(대소문자까지 — Mac에선 열려도 GitHub Pages에선 404). `#id` 링크(크럼의 `index.html#가족`, 허브 브랜드 칩)의 대상 id가 실제로 있는지(수첩의 `#settings` 같은 화면 경로는 제외). 루트·`tax/`의 모든 페이지에서 상단 내비가 정확히 [수첩, 자동차세, 유지비 비교]이고 현재 위치(`aria-current="page"`)가 맞는지, 푸터 2번째 줄이 [소개·문의, 개인정보처리방침, 이용약관] 순서인지, 손 페이지 head에 `<!-- adsense:head -->` 마커가 있는지. 손 페이지마다 있어야 할 광고·문의 마커(`tco.html`의 `adsense:slot tcoEnd`, `privacy`·`terms`·`about`의 `site:contact`)가 정확히 한 번 있고 다른 페이지에는 없는지(마커를 지우거나 이름에 오타가 나면 빌드는 그 자리를 조용히 비우고 통과하므로 여기서 잡아요). `about.html`이 아직 없던 시기(공통 크롬 도입 전)에는 크롬 불일치를 '참고'로만 보여요 |

CI는 메인 job에서 위 검사를 단계별로 돌리고(빌드 최신 여부는 `check.py build`, 링크는 `check_links.py`), 사용자 Mac과 같은 Python 3.9로도 `scripts/check.py`를 한 번 더 돌려 3.10 이상 전용 문법이 섞이면 알려 줍니다.

**실패하면** 메시지의 '→' 또는 '고치는 법'대로 고친 뒤 다시 돌리세요. 자주 나오는 경우:

- 빌드 결과가 최신이 아니에요 → `python3 scripts/build.py` 실행 후 생성물을 바뀐 것·새로 생긴 것·지워진 것까지 모두 같이 커밋: 메시지에 나온 `git add tax og icons favicon.ico robots.txt sitemap.xml …` 줄(이번에 바뀐 `ads.txt`·손 페이지까지 들어 있어요)을 그대로 쓰거나 `git add -A`(작업 중인 다른 파일까지 담기니 `git status`로 먼저 확인). '지워짐'은 빌드가 더 이상 만들지 않는 페이지·썸네일이라 빌드를 돌리면 작업 폴더에서도 지워져요. `sitemap.xml`은 날짜만 바뀐 건 커밋하지 않아도 통과해요. 1월 1일이 지나 연도가 바뀌면 전 페이지가 바뀌는 게 정상이니 새해에 한 번 빌드해 커밋하세요.
- 세액 불일치 → `build.py`의 `tax_for`·`prepay`와 `js/tax-calc.js`의 `taxFor`·`prepay` 중 한쪽만 고친 상태. 두 곳의 계산 순서·10원 미만 절사를 똑같이 맞추세요.
- 데이터 오류 → 메시지에 파일·몇 번째 항목(id)·줄 번호·필드가 나와요. 배기량을 모르면 추정하지 말고 `null`로 두세요(경고만 뜨고 그 차종 페이지는 빠짐).
- 공통 크롬 불일치 → `tax/` 페이지는 `scripts/build.py`의 `page()`·`topbar_nav()`·`footer_links()`를 고치고 빌드하세요. 손 페이지는 메시지에 나온 계약 마크업을 그대로 붙여 넣으세요.
- 없는 `#id` → 링크를 만드는 쪽과 id를 만드는 쪽(허브의 slug 기반 id)이 어긋난 상태. 같은 함수로 맞추세요.
- 광고 금지 페이지에 광고 → `index.html`·`about.html`·`privacy.html`·`terms.html`에서 그 줄을 지우세요(아래 '수첩에 광고를 넣지 않는 이유', 개인정보처리방침 4절).
- 광고·문의 마커가 없어요·계약에 없는 마커 → 마커를 지웠거나 이름에 오타(`tcoend`)가 난 상태. 메시지에 나온 빈 형태 마커를 그 페이지에 그대로 넣으세요.

## 애드센스 켜고 끄기

광고는 `data/site.json`의 `adsense` 값만으로 켜고 끕니다. 코드는 고치지 않아요.
값을 바꾸면 **반드시 빌드하고, 빌드가 바꾼 파일(`ads.txt`·손 페이지 마커·`tax/`)을 같이 커밋**하세요 — 안 그러면 빌드 검사가 실패해요.

| 값 | 비어 있으면 (`""`) | 채우면 |
|---|---|---|
| `publisherId` — 애드센스 '게시자 ID', `pub-` + 숫자 16자리 (앞에 `ca-` 없이) | 광고 코드·`ads.txt`·소유 확인 메타가 하나도 없음 | 루트 `ads.txt` 한 줄(`google.com, pub-…, DIRECT, f08c47fec0942fa0`) + 모든 페이지 head에 `<meta name="google-adsense-account" content="ca-pub-…">` |
| `slots.taxArticle`·`hubEnd`·`calcEnd`·`tcoEnd` — 광고 단위 ID(숫자) | 그 자리에 광고 없음 | 그 자리에 광고 1개(차종 페이지 '계산 방법' 뒤 / 차종 목록 끝 / 계산기 끝 / 유지비 비교 끝) + 그 페이지 head에만 `adsbygoogle.js` |

1. **켜기 — 게시자 ID와 사이트 소유 확인**
   ```bash
   # data/site.json:  "adsense": { "publisherId": "pub-0000000000000000", ... }   ← 실제 게시자 ID로
   python3 scripts/build.py     # '· ads.txt 생성', '· index.html 광고·문의 마커 갱신' 같은 줄이 나와요
   python3 scripts/check.py
   git status                   # ads.txt·손 페이지·tax/ 가 바뀐 것 확인
   git add -A
   git commit -m "feat: 애드센스 게시자 ID 설정"
   git push
   ```
   배포 뒤 https://chailji.com/ads.txt 를 열어 한 줄이 보이는지 확인하고, 애드센스 사이트 소유 확인 방법은 **메타태그**를 고릅니다
   (수첩 홈에는 광고 코드가 없고 소유 확인 메타만 있어요).
2. **승인 후 — 광고 단위 4개**: 애드센스의 광고 단위 메뉴에서 디스플레이(반응형) 광고 단위를 자리마다 하나씩 만들고,
   ID(숫자)를 `slots`의 같은 이름에 넣은 뒤 1번처럼 빌드 → 검사 → 커밋 → push.
3. **끄기**: `publisherId`와 `slots`를 모두 `""`로 비우고 빌드 → 검사 → `git add -A` → 커밋. 빌드가 `ads.txt`를 지우고
   ('· ads.txt 삭제(publisherId 비어 있음)'), 메타·광고 코드가 0이 되며 손 페이지 마커는 빈 형태로 돌아가요(손 페이지 diff 0).
4. **계정을 옮길 때**: 애드센스 계정은 다른 사람에게 이전할 수 없어 새 계정을 만듭니다. 새 계정에 사이트를 추가하고 옛 계정에서 빼고,
   `publisherId` 한 줄만 바꿔 1번처럼 빌드·커밋하면 `ads.txt`·메타가 함께 바뀌어요(슬롯 ID도 새 계정 것으로).

자주 하는 실수: `ca-pub-…`를 그대로 넣기(→ 데이터 검사가 '앞의 ca-를 지우세요'), 값만 바꾸고 빌드를 안 돌리기(→ 빌드 검사가
`ads.txt`·손 페이지를 '새로 생김'·'바뀜'으로 잡음), 광고 단위 ID에 따옴표를 빼기(→ 데이터 오류).

## 문의 이메일 설정

`data/site.json`의 `contactEmail`에 **사이트 전용** 문의 주소를 넣습니다(개인 메일은 쓰지 않아요). 빌드 → 검사 → `git add -A` → 커밋.
개인정보처리방침·이용약관·소개 페이지의 `<!-- site:contact -->` 자리에 `이메일: 주소` 문단이 생겨요.
비워 두면(`""`) 그 문단이 없고, 문의 수단은 GitHub 이슈만 보입니다.

## 손 페이지 마커 규칙

손으로 쓰는 루트 페이지에서 빌드가 `site.json` 값으로 채우는 자리는 아래 마커뿐이에요. **값이 비었을 때는 여는 마커와 닫는 마커가
공백·줄바꿈 없이 붙은 이 문자열 그대로** 둡니다 — 그래야 빌드 후 손 페이지 diff가 0이에요.

| 마커 (빈 형태) | 두는 곳 | 채워지는 것 |
|---|---|---|
| `<!-- adsense:head --><!-- /adsense:head -->` | 모든 손 페이지의 `<head>` 안 (빠지면 링크 검사가 잡음) | 소유 확인 메타. 그 페이지에 채워진 슬롯이 있으면 `adsbygoogle.js`도 |
| `<!-- adsense:slot tcoEnd --><!-- /adsense:slot -->` | 손 페이지의 광고 자리 (지금은 `tco.html`의 `</main>` 바로 앞. 빠지거나 이름이 틀리면 링크 검사가, 이름 오타는 데이터 검사도 잡음) | 광고 슬롯 마크업 (`slots.tcoEnd`가 있을 때) |
| `<!-- site:contact --><!-- /site:contact -->` | `privacy.html`·`terms.html`·`about.html`의 문의 문단 (빠지면 링크 검사가 잡음) | `<p>이메일: <a href="mailto:…">…</a></p>` (`contactEmail`이 있을 때) |

- 빌드는 마커 **안쪽만** 바꾸고 바깥은 한 글자도 건드리지 않아요. 마커 안을 손으로 고치면 다음 빌드에 덮여요.
- 닫는 마커가 없거나, 같은 마커가 두 번이거나, 마커가 겹치거나, 형식(띄어쓰기 한 칸)이 다르면 빌드가 파일 이름·줄을 알리고 멈춰요.
- slot 마커의 이름(`tcoEnd`처럼 영문으로 시작하는 영문·숫자)은 `slots`의 키와 같아야 해요(다르면 데이터 검사가 오류로 잡아요). 페이지당 광고 자리는 1개예요.
- `index.html`(수첩)에는 `adsense:slot`을 넣을 수 없어요 — 빌드가 오류로 멈추고 빌드 검사도 실패해요. head 마커만 둡니다.
  소개·개인정보처리방침·이용약관에도 넣지 않아요 — 빌드 검사와 링크 검사가 실패해요.

## 수첩에 광고를 넣지 않는 이유

`index.html`(수첩 — 첫 방문 소개 화면 포함)에는 광고 자리를 두지 않고, head의 소유 확인 메타 자리만 둡니다.

- 입력·설정 화면, 알림·탐색 같은 행동 목적의 화면에는 Google 광고를 게재할 수 없어요(게시자 정책).
- 수첩은 버튼이 촘촘하고 하단 토스트가 떠서, 광고(특히 화면 아래 앵커 광고)가 버튼·토스트와 겹쳐 실수 클릭을 부릅니다.
- 화면을 자바스크립트로 다시 그리기 때문에 광고가 그릴 때마다 다시 요청돼요.
- 페이지에 실린 광고 스크립트는 그 페이지의 내용을 읽을 수 있어요. 수첩 기록이 보이는 화면에는 광고 스크립트를 싣지 않는다는
  개인정보처리방침의 약속('수첩 화면에는 광고 스크립트를 싣지 않습니다')을 지키기 위해서이기도 해요.

빌드 검사가 `index.html`에서 `adsense:slot`·`adsbygoogle`을 찾으면 실패합니다(소개·개인정보처리방침·이용약관도 같은 검사).

## 자동 광고·광고 인텐트·비네트는 끈 채로 운영

광고는 위 수동 광고 단위 4자리만 씁니다. 애드센스의 사이트별 광고 설정에서 **자동 광고를 끈 상태**로 두고, 특히 아래 둘은 켜지 마세요.

- **광고 인텐트**: 본문 글자에 광고 링크를 끼워 넣어요 — 세율·설명 문장이 광고 링크가 됩니다.
- **비네트**: 페이지를 옮길 때 전면 광고를 띄워요 — 허브 → 차종 페이지 흐름을 가립니다.

자동 광고의 '페이지 제외'는 URL 단위라 `?demo=1` 같은 주소를 뺄 수 없고, 앵커처럼 화면 위에 뜨는 광고에는 '제외 영역'이 적용되지
않아 수첩·입력 화면을 지킬 수 없어요. 유럽(EEA·영국·스위스) 방문자용 동의 메시지는 애드센스 > 개인 정보 보호 및 메시지 >
유럽 규정에서 무료 Google 인증 메시지를 만들어 두면 광고 코드가 알아서 불러옵니다(코드 수정 없음).

## 큰 변경 뒤 화면 확인

여러 화면을 한꺼번에 바꾼 뒤에는 `python3 scripts/build.py`와 `python3 scripts/check.py`를 통과시킨 다음, 375px(모바일)과 1280px(PC)에서
홈(첫 방문·`?demo=1`), 차종 목록, 차종 페이지(판매 중·단종 세대·전기·화물 각 1개), 계산기, 유지비 비교(입력 완료), 개인정보처리방침,
이용약관, 소개를 열어 봅니다.

- 가로 스크롤이 없다(페이지 폭 = 화면 폭).
- 브라우저 기본 파랑·보라 링크가 없다. 브레드크럼·출처 링크는 회색(muted)이다.
- 광고를 켤 때는 저장소 **사본**에서 `publisherId`·`slots`·`contactEmail`을 채워 빌드한 뒤, 광고 자리가 첫 화면 밖이고 위아래 버튼·링크와
  60px 이상 떨어져 있는지, 광고가 늦게 떠도 본문이 밀리지 않는지(CLS 0.01 이하), 문의 이메일 문단이 보이는지 확인합니다.
